## 1. The Verification Problem in Learning Systems

In general software engineering, a JSON record that parses without syntax errors and validates against a schema is considered "valid". 

**In an IELTS Tutoring System, syntactic validity is completely insufficient.**
- An extracted question might look syntactically perfect, but OCR noise may have garbled a negative particle (e.g. `not` turned into `hot`), inverting the truth value of a True/False statement.
- An answer key might be an unverified student answer sheet rather than the official Cambridge examiner key.
- An explanation might be hallucinated by an LLM and falsely claim that a passage mentions a detail that is actually `NOT GIVEN`.

Phase V0.2 establishes an uncompromising, multi-dimensional quality framework governed by the **Golden Rule of IELTS Data Systems**:
> **A syntactically valid JSON record is not necessarily a verified learning record. Machine-generated explanations and answers must NEVER be classified as official answer keys.**

## 2. Multi-Dimensional Quality Classification

Every normalized entity carries five independent quality vectors rather than a single monolithic status field:

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                      FIVE-DIMENSIONAL QUALITY PROFILE                           │
├───────────────────────────────┬─────────────────────────────────────────────────┤
│ 1. Extraction Quality         │ Fidelity of physical text/data capture          │
│ 2. Source Fidelity            │ Authority of the originating document           │
│ 3. Answer Verification        │ Ground-truth certainty of the answer key        │
│ 4. Explanation Verification   │ Pedagogical grounding of the reasoning          │
│ 5. Publication Permission     │ Legal redistribution and copyright classification│
└───────────────────────────────┴─────────────────────────────────────────────────┘
```

### 2.1 Extraction Quality (`extraction_quality`)
Measures whether the raw text capture suffered from OCR noise, parsing truncation, or segmentation anomalies.
- `complete_clean`: Digital extraction (DOCX, pure PDF text) with 100% character fidelity and zero dropped blocks.
- `ocr_noisy`: Scanned text with minor character substitution (e.g. `Í` instead of `it`, `senes` instead of `series`). Requires regex or human de-noising.
- `segmented_imperfect`: Extracted sentences contain concatenated question runs or broken table columns that were heuristically recovered.
- `truncated_missing_pages`: Source physical file has missing pages (e.g. `SRC-137` starting on book page 95 and missing Question 1).

### 2.2 Source Fidelity (`source_fidelity`)
Classifies the bibliographic authority of the source publication.
- `authoritative_official`: Authentic Cambridge IELTS examination papers or British Council / IDP official preparation material.
- `secondary_reputable`: Recognized third-party prep materials with verified editorial staff (e.g., Ngoc Bach Writing Handbook, Collins IELTS).
- `unverified_community`: Community transcriptions, unverified student answer keys, or shared internet question compilations.

### 2.3 Answer Verification (`answer_verification`)
Classifies the epistemic truth of the answer key value.
- `authoritative_key`: Printed in the publisher's official answer key section and cross-verified against the passage text.
- `consensus_key`: Confirmed by multiple independent secondary sources (e.g. matching both an XLSX key and a teacher explanation book).
- `unverified`: Extracted from a community sheet or single unreviewed source; pending expert verification.
- `disputed`: Conflicting keys published across different volumes or identified as erroneous by expert consensus.

### 2.4 Explanation Verification (`explanation_verification`)
Classifies the pedagogical rationale.
- `source_provided`: Printed directly in the original published examination study guide.
- `expert_verified`: Authored, reviewed, and approved by a certified human IELTS tutor (Band 8.5+ / 9.0).
- `machine_drafted_unverified`: Generated by AI models or heuristic rules; strictly quarantined from high-stakes quizzing until reviewed.
- `unsupported`: Missing textual citation or lacking observable distractor analysis.

### 2.5 Publication Permission (`publication_permission`)
Enforces legal copyright boundaries.
- `public_synthetic`: Synthetic test items, illustrative examples, and repository principles authorized for public Git tracking.
- `private_copyrighted`: Full authentic Cambridge exam papers and commercial books. Must reside exclusively under gitignored `private/` storage.
- `restricted_citation`: Brief fair-use quotations (1–2 sentences) used exclusively for evidence grounding in learning logs.

## 3. Entity Lifecycle & Permitted State Transitions

Normalized entities progress through a formal state machine:

```
                     ┌───────────────┐
                     │   EXTRACTED   │
                     └───────┬───────┘
                             │ Normalizer validation
                             ▼
                 [Are all gates satisfied?]
                    /                 \
            YES   /                     \  NO (anomalies / missing data)
                ▼                         ▼
        ┌───────────────┐         ┌─────────────────┐
        │   REVIEWED    │         │ REVIEW_REQUIRED │
        └───────┬───────┘         └────────┬────────┘
                │                          │
                │ Human Expert Review      │ Human remediation
                ▼                          ▼
        ┌───────────────┐         ┌─────────────────┐
        │   VERIFIED    │         │    REJECTED     │
        └───────────────┘         └─────────────────┘
```

### 3.1 State Definitions
1. `extracted`: Initial state assigned automatically by the normalizer upon schema compliance. All fields populated, but no human review conducted.
2. `review_required`: Flagged automatically if any anomaly is detected (e.g. OCR noise, missing parent question, truncated answer key, ungrounded evidence quote).
3. `reviewed`: Validated by an automated multi-source consistency check or preliminary pedagogical audit.
4. `verified`: Certified by a human expert tutor as 100% faithful to exam truth and pedagogy. Authorized for high-stakes learner diagnostic tracking.
5. `rejected`: Identified as fatally corrupted, misattributed, ungrounded, or pedagogically unsound. Excluded from query indexes.

### 3.2 State Transition Matrix & Gate Rules

| Initial State | Target State | Permitted Actor | Required Pre-conditions & Evidence |
|---|---|---|---|
| `extracted` | `reviewed` | Automated Pipeline | No warning flags, exact evidence quote matches passage verbatim, and answer key is from authoritative source. |
| `extracted` | `review_required` | Automated Pipeline | Any flag triggered: `MISSING_ANSWER_KEY`, `UNRESOLVED_EVIDENCE_SPAN`, `OCR_CORRUPTION_DETECTED`, or `CONCATENATED_QUESTION_RUN`. |
| `review_required`| `reviewed` | Human Data Engineer | Concatenation fixed, missing question transcribed from physical source, or OCR noise repaired. |
| `reviewed` | `verified` | Human IELTS Expert | Answer verified against original passage logic; explanation checked for absence of hallucination. |
| Any State | `rejected` | Human Expert or Pipeline | Irreparably corrupted scan, conflicting unresolvable answer keys, or completely ungrounded reasoning. |
| `verified` | Any State | Disallowed | Downward transitions from `verified` require administrative override and logged justification. |

## 4. Verification Gates Implementation

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│ GATE 1: INGESTION CHECKSUM GATE                                                 │
│ • Check: raw_sha256 matches SQLite checkpoint database                          │
│ • Failure: Halt pipeline; emit IntegrityError                                   │
└──────────────────────────────────────┬──────────────────────────────────────────┘
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ GATE 2: SYNTACTIC & ENUM GATE                                                   │
│ • Check: Conforms to JSON Schema; enums belong to controlled vocabularies       │
│ • Failure: Reject record; emit SchemaValidationError                            │
└──────────────────────────────────────┬──────────────────────────────────────────┘
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ GATE 3: REFERENTIAL INTEGRITY GATE                                              │
│ • Check: passage_id, group_id, question_id resolve in database                  │
│ • Failure: Assign review_required; emit ORPHAN_FOREIGN_KEY                      │
└──────────────────────────────────────┬──────────────────────────────────────────┘
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ GATE 4: EVIDENCE GROUNDING GATE                                                 │
│ • Check: verbatim_quote exists exactly in passage text at char_start:char_end   │
│ • Failure: If fuzzy match > 0.85 -> review_required; If < 0.85 -> UNRESOLVED    │
└──────────────────────────────────────┬──────────────────────────────────────────┘
                                       ▼
┌─────────────────────────────────────────────────────────────────────────────────┐
│ GATE 5: PEDAGOGICAL INTEGRITY GATE                                              │
│ • Check: AI-generated explanations flagged machine_drafted_unverified;          │
│          Answer keys verified against authoritative publications.               │
│ • Failure: Prevent promotion to verified status                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```
