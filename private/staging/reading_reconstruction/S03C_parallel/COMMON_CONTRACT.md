## Batch definition
One source passage and all its actual question groups, numbered slots, assets and key-status records. Enumerate source pages/paragraphs independently, including adjacent/cross-page blocks, source misnumbering and missing questions. Keep canonical mapping separate from source identity; account for missing/orphan/combined slots without inventing entities. Historical population 111 passages, 303 groups, 1444 candidate items/1463 slots is a reconciliation baseline, not a quota. Multi-select item and scoring slots are separate. Read original PDF rendered layout or DOCX XML/table/image order; XLSX keys by exact sheet/cell. OCR is a candidate transcription only. Reuse existing extracts where their source hash and locators resolve. A second parser, fuzzy score, nonempty field, source format or passage ID is not proof.

## Required actual values (not instructions)
Per batch use the frozen gate schema; retain S03B bundle names passage_reference.json, question_groups.jsonl, questions.jsonl, answer_keys.jsonl, canonical_mapping.jsonl, source_limitations.jsonl. Include ordered passage paragraphs, headings and source block locators, exact instructions and context, ordered options, numbered blanks mapped to their positions, shared options, diagram/table assets with content hashes and locators, required answer counts, word limits, key availability and authority. For cloze, provide actual group_context_verbatim with all numbered positions and map each question to the relevant position; avoid duplicating unrelated text. Source oddities must be preserved verbatim with separate display normalization. Never fill gaps from canonical JSON, infer missing source keys, or replace wording with a plausible paraphrase. Do not use proposed_after_value={requires_group_context_verbatim_from_source:true,...} as a completed correction. All 77 such instructions need actual context or a documented source limitation. Preserve orphan keys out of practice scope. Verify answer normalization by question type (F option stays F), full multi-select set, labels, distinct answers, cardinality and constraints. Source key transcription is not verification of answer authority. For no supplied key, create explicit missing-key record, not a fake value.

## Evidence and review
Each authored field must have a source locator and evidence hash (or ordered source-span IDs with deterministic comparison) tied to a source document hash. Store independent review events binding exact entity field and actual content hash, source locator, expected value or source-span reference, comparison method/outcome and reviewer identity/session. For scanned/ambiguous layout, compare directly with rendered source regions; for digital text, exact comparison to independently delimited source spans may suffice; verify order and coverage. Reuse earlier confirmed evidence only if it demonstrably covers the exact field, content hash and source locator. Review authors cannot approve their own substantive changes. If reviewer must suggest new wording, author creates a new revision and a different session confirms only changed fields and dependencies. Reject instructions masquerading as actual values. Do not self-approve by declaring a passage digitally inspected. Separate human/agent evidence from deterministic mechanical checks; a gate can verify attestation linkage and consistency, not independently prove OCR semantics. Use 2 bounded correction attempts, then HOLD_MANUAL_REVIEW. Never rerun the whole volume solely to fix one record.

## Distinct scopes
- SOURCE_REFERENCE_CONFIRMED: faithfully transcribed including explicit limitations, not automatically usable.
- PRACTICE_READY: all passage, question, instructions, context, asset, mapping dependencies verified; no blocking practice defect. Missing keys alone do not block this scope. Practice-only items must not be automatically graded; preserve answer hiding.
- RESTRICTED_PRACTICE: explicit eligible subset of slots with complete dependency closure, never present as a complete test/passage; omitted slots listed. If no complete usable group exists, reading-only or hold.
- GRADING_KEY_AVAILABLE_UNVERIFIED: supplied answer transcription confirmed but authority unverified, feedback must label uncertainty; no diagnostic band claim. Missing/ambiguous/invalid keys -> GRADING_DISABLED per slot/group. Authoritative diagnostic grading only where existing contract genuinely supports it; never promote keys for coverage.
- PASSAGE_ONLY: verified body but omitted/unusable questions. HOLD: unresolved source/semantic/evidence dependencies.
