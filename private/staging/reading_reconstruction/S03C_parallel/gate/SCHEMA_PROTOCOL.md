# S03C gate v1

One immutable revision covers one source passage and its source question groups, numbered slots, assets and key records. The gate reads explicit paths and emits scope decisions for that revision. The field definitions in `gate.py` and evidence rules in `evidence.py` are executable requirements. Historical S03B bundles are inputs to reconstruction and need materialized S03C records and a new review receipt.

## Files and records

Each file uses UTF-8. JSONL files contain one object per line and can be empty where the corresponding population is zero. Keys, entity IDs within a file and span IDs are unique. The tables list required fields. IDs are stable nonempty strings and type references resolve within the revision unless specified below.

| File | Required fields and meaning |
|---|---|
| `passage_reference.json` | `id`, `volume`, integer `test`, integer `passage_number`, `source_id`, nullable verbatim `title` and `subtitle`, ordered `paragraphs`, `body_sha256`, ordered `slots`, `asset_ids`. Paragraphs contain `label` (nullable), verbatim `text` and ordered `spans`. Slots contain `id`, printed `number` (positive integer, source anomaly string, or null for an absent number), nullable `group_id`, nullable `question_id` and `span`. Preserve unusual printing in the source text and locator. Slot IDs and mappings provide stable display and canonical references. |
| `question_groups.jsonl` | `id`, `passage_id`, `source_id`, `question_type`, verbatim `instruction`, nullable verbatim `context`, ordered `shared_options`, ordered distinct permitted `labels`, positive integer `required_answer_count`, nullable `word_limit` with nonnegative integer `words` and `numbers`, and `asset_ids`. The `context` field is the complete group context verbatim for cloze, with all numbered blank tokens. Option entries contain a printed `label` and verbatim `text`. |
| `questions.jsonl` | `id`, `passage_id`, `source_id`, `group_id`, ordered `slot_ids`, verbatim `prompt` or null for a cloze item whose prompt is in context, ordered `options`, `blanks`, `asset_ids`. Each blank is keyed by slot ID with integer `start` and `end` (zero-based Unicode code-point offsets, end exclusive) and exact `token` within the group context. Multi-select has one item and multiple slots. |
| `answer_keys.jsonl` | `id`, `passage_id`, nullable `source_id`, nullable `question_id`, nullable `orphan_number`, `status`, nullable verbatim `raw`, `values`, nullable `alternate_separator`, `authority`. One record per question. An orphan has `status: "orphan"`, a positive `orphan_number`, a source locator and no question target. It never adds a practice slot. |
| `canonical_mapping.jsonl` | `id`, `entity_type` (`passage`, `group`, `question`, `key`), `reference_id`, `canonical_ids`, `canonical_slots`. One row per source entity, with empty arrays for unmapped entities. A mapped question gives one independent canonical question ID per source slot and `canonical_slots` maps each such ID to its slot ID. Other rows use an empty object. Targets resolve by type against the explicitly supplied frozen S01 Reading entity inventory. The gate checks canonical passage identity, group parentage, question number and key linkage. A documented legacy group or numbering discrepancy withholds the affected dependency. Independently reviewed source groups may share a legacy group ID if the historical group combined them. |
| `source_limitations.jsonl` | `id`, `target_type` (`passage`, `group`, `question`, `slot`, `key`), `target_id`, `kind` (`source_defect`, `pending`, `unresolved`), nullable `field`, `reason`, `attempts`. `pending` names the exact target field and records 0–2 failed correction attempts. Two attempts require `HOLD_MANUAL_REVIEW` for that target. An evidenced `source_defect` describes what the original prints or omits. `unresolved` records outstanding evidence or uncertainty. |
| `evidence_manifest.json` | `spans`, `assets`, and `fields` defined below. |
| `batch_manifest.json` | `schema: "S03C-gate-v1"`, `scope` (the passage's `id`, `source_id`, `volume`, `test`, `passage_number`), `source_sha256`, `canonical_inventory_sha256`, `author` (`id`, `session`), `files` mapping the seven payload files above to raw SHA-256, and `population` with `passage`, `group`, `question`, `key`, `mapping`, `limitation` and `slots` counts. |

A distinct slot ID represents each source position. One printed number can appear in multiple positions under explicit source limitations. Represent a missing position with a slot and a limitation when the source's rubric calls for it. Preserve a source-defective option bank with its printed labels and order and record the defect. A missing diagram is represented by omitting its asset ID and recording the limitation. A referenced asset must exist. Text-only instructions, todo objects and empty cloze context do not meet cloze practice requirements.

`available` keys require an exact transcription. `missing` has null source, raw value and separator, empty `values` and authority `missing`. `ambiguous`, `invalid`, `pending` and `orphan` preserve supplied text and use empty `values`. All supplied material has authority `unverified` in this gate. Use a matching source inventory entry for the key, including the correct volume and test. Multi-select takes comma-delimited native span text and requires the complete distinct set of supported labels at the recorded cardinality. For a key spread over cells, transcribe each cell verbatim and use a native set representation as described below. Option and matching questions preserve exact labels, including `F`. Boolean aliases apply only to the corresponding boolean type. Free-text keys use null or slash alternate separator. Each alternate is checked against the group's word and number limits. Hyphenated tokens count as one token. Integer/decimal tokens with punctuation and dates written in digits count as numbers when the source permits numbers. Use an explicit limitation and disable grading when the rule or transcription cannot be represented reliably.

## Hashes and evidence

- Raw file digests are lowercase hexadecimal SHA-256 over bytes. The gate reads the frozen `source_inventory.jsonl` and recomputes every referenced original's digest. The caller supplies both S01 inventories as trusted inputs. The manifest pins the byte hash of the canonical inventory. Evidence and asset paths are relative to the explicit workspace, with traversal and external symlink targets rejected.
- Canonical JSON uses Python 3.12 `json.dumps(value, sort_keys=True, ensure_ascii=False, allow_nan=False, separators=(",", ":")).encode("utf-8")`. Preserve array order, whitespace in values and Unicode code points. There is no normalization or trailing newline. `body_sha256` hashes the entire ordered paragraph array, including labels and span IDs. The revision hashes the canonical batch manifest. A field digest hashes the canonical JSON value alone. The reviewer receipt binds the revision, qualified entity ID, field, digest, exact expected value, method, outcome and evidence span IDs.
- A span contains `id`, `source_id`, `source_sha256`, `locator`, `text` and nullable `file`. Its ID hashes the canonical object containing exactly `source_id`, `source_sha256` and `locator`. PDF locators carry one-based physical `page` and `box` of integer coordinates `[left, top, right, bottom]` scaled to 0–10000 across the page as rendered, with origin at the upper left. `pdfinfo` resolves the page count. Digital PDF spans may add `native_chars`, a pair of zero-based Unicode offsets with exclusive end into that physical page’s exact `pdftotext -layout -nopgbrk -enc UTF-8` output. The gate recomputes the excerpt and requires exact equality. DOCX locators carry `element`, a nonempty list of zero-based child indices relative to `word/document.xml`'s `w:body`, including indices through tables and nested elements. Native text concatenates descendant text and preserves Word tabs and breaks. All top-level DOCX blocks between the reviewed boundary anchors must appear in the region ledger, including explicitly excluded blank blocks. XLSX locators carry exact `sheet` and uppercase A1 `cell`. Cell values resolve through workbook relationships and shared strings when present. Preserve complex layout in referenced assets and attest its reading order.
- `file` entries contain `path` and `sha256`. A null file uses the original document and locator directly. Pin any separately used render, extract or crop in `file`. An asset contains `id`, its source `span` ID, and a nonempty hashed `file`. The asset field receipt cites that span and binds the file hash through the manifest. For a native table or diagram, attach the verified block image or structured serialization and attest the interpretation against the original region.
- `fields` maps `kind/id` to field name to ordered span IDs. Kinds are the record types in the schema. Every actual field, including nulls, dependencies and populated arrays, needs nonempty evidence. Source absence needs an anchor in the passage, rubric or inspected relevant key evidence. Compare exact verbatim strings to the space-joined span text. Layout-derived fields such as structured options are compared to the reviewer's independently recorded expected value. Review of OCR and ambiguous layout uses the rendered original region.
- For multi-select with multiple native cells, each span carries its cell's exact text. The ordered span sequence is one item-level evidence unit. The source text is joined with a comma and space before key normalization. The gate checks the complete set and never treats two independent single-choice keys as a combined item absent an independently verified group, item and slot relationship.

## Reviewer receipt and scope

Store the receipt outside the author revision in the reviewer's own write area. It is JSON with `schema`, `revision`, `scope`, `reviewer` (`id`, `session`), `body_regions`, `question_census` and `fields`. Author and reviewer IDs and session IDs are independently assigned identifier strings and must differ case-insensitively. The coordinator obtains the receipt's raw SHA-256 from the reviewer through a trusted channel and pins it in the command. Do the same for regenerated receipts. A hash that an author supplies for their own file conveys no reviewer trust.

Each reviewer field event contains `actual_sha256`, `expected` (independently compared value), ordered `spans`, `method` (`rendered`, `native` or `derived`) and `outcome: "match"`. `native` applies to exact DOCX, XLSX and digital PDF extracts. Verbatim text from a visual-only PDF region requires `rendered`. `derived` is for verified structure, constraints, normalization and mapping that depend on the source spans. Reviewers check the exact fields, question and slot census, instructions, all blank positions, assets, ordering, and mapping. Reviewer-proposed wording requires a new author revision and different review session. For an unresolved source issue, the reviewer can confirm the evidence and the documented limitation without approving the unresolved content.

Independently enumerate actual group IDs and ordered slot records in `question_census.groups` and `question_census.slots`. Census `adjacent_rubrics` maps any out-of-scope rubric boundary span to the reason it belongs to another scope. The gate checks explicit numbered rubric headings in the body boundary and group instructions against the slot inventory, verifies that eligible slot evidence includes its printed number and rejects recognized numbered cloze markers without an exact blank mapping. Preserve atypical printed numbering with explicit limitations.

Independently delimit the full body window and record ordered `body_regions`. Each row contains `role`, ordered `spans` and nullable `label`. Start with `before` and end with `after`, using source-backed anchors on both sides. Select each `title`, `subtitle` and `paragraph` independently and label intervening non-body blocks `excluded`. Source leading text, page furniture and question sections require explicit exclusion where they are inside the inspected window. A cross-page paragraph cites each piece in order. For page-spanning windows, account for each physical page. Reviewers check reading order for multiple columns. The gate builds the paragraph array from these segments and checks exact order, coverage, identity and hashes.

The gate checks the consistency of the attestation and its evidence. The independent reviewer establishes what a scanned region means and whether the chosen region inventory covers the complete source. Hashes cannot establish reviewer identity or publisher answer authority.

- `SOURCE_REFERENCE_CONFIRMED` includes explicit, evidenced source defects. Unresolved dependencies, pending corrections and invalid supplied-key claims yield `HOLD` in reference scope.
- `PRACTICE_READY` requires passage and complete question group dependencies. An evidenced practice limitation removes its complete affected group. The gate emits `RESTRICTED_PRACTICE` with exact eligible and omitted slot IDs when usable groups remain. A verified body with no usable source group yields `PASSAGE_ONLY`. Unresolved semantic/content dependencies without a usable group yield `HOLD` or `HOLD_MANUAL_REVIEW`.
- The gate emits `GRADING_KEY_AVAILABLE_UNVERIFIED` per eligible scoring slot only when a supplied key transcribes correctly and passes constraints. Missing keys, pending key-only corrections and excluded slots yield `GRADING_DISABLED`. Honor answer hiding and disable diagnostics. The gate issues no corpus acceptance or publication authorization.

## Invocation

Run from the repository root with the repository virtual environment and Poppler's `pdfinfo` and `pdftotext` on PATH. The historical PDF regression also uses the originals below `private/raw/`. The CLI reads the provided revision and receipt and prints JSON. Optional `--result` must name a new `gate_result.json` in the caller's authorized output directory. It is published atomically without replacing an existing file. Omit the option for read-only reruns.

```bash
gate=private/staging/reading_reconstruction/S03C_parallel/gate
./.venv/bin/python -B "$gate/gate.py" \
  --workspace "$PWD" \
  --inventory private/staging/reading_reconstruction/S01_freeze_containment/source_inventory.jsonl \
  --canonical-inventory private/staging/reading_reconstruction/S01_freeze_containment/reading_entity_inventory.jsonl \
  --batch "$author_revision" --review "$independent_receipt" \
  --review-sha256 "$reviewer_supplied_sha256"
```

Exit 0 indicates a mechanically valid decision with an available practice or passage scope. A key-only hold may coexist with that decision. Exit 1 indicates a validation error or held practice. Inspect each scope and the blockers in every result. Exit 2 indicates invalid arguments or a failed result write.
